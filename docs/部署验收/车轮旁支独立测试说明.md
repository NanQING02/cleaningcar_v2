# 车轮旁支独立测试说明

本文用于板端单独验证车轮旁支，不启动主相机检测链路。测试目标是确认：

- 左右车轮 RTSP 可读。
- 车轮 RKNN 模型可加载并推理。
- 车轮结果可进入缓存、绑定、分桶、代表图选择。
- 车轮照片可落盘。
- `POST /api/vehicle/wheel-photo` 可到达 PC 端 mock 接口。

## 1. 打包文件

仓库内生成的推荐传输包：

```bash
packages/wheel_sidechain_test_kit.tar.gz
```

包内文件名全部为英文 ASCII，推荐在 Linux 板端使用：

```bash
tar -xzf wheel_sidechain_test_kit.tar.gz
```

解压后目录：

```text
wheel_sidechain_test_kit/
  tools/
    wheel_sidechain_probe.py
    run_wheel_probe_board.sh
    mock_wheel_photo_api.py
    wheel_sidechain_test_README.md
```

## 2. PC 端启动 mock 接口

在 PC 端项目根目录运行：

```bash
python tools/mock_wheel_photo_api.py --host 0.0.0.0 --port 28014
```

记下 PC 的局域网 IP，例如：

```text
192.168.1.100
```

板端要使用的上报地址就是：

```text
http://192.168.1.100:28014/api/vehicle/wheel-photo
```

PC 端收到请求后会打印：

```text
[POST] path=/api/vehicle/wheel-photo photoUrl=... type=4 cleanValue=2
```

PC 端保存文件：

```text
mock_api_output/YYYYMMDD_HHMMSS/
  requests.jsonl
  wheel_photo_requests.jsonl
  wash_event_requests.jsonl
```

## 3. 板端运行方式

把 `wheel_sidechain_test_kit.tar.gz` 传到板端 CleaningCar 项目根目录，然后：

```bash
tar -xzf wheel_sidechain_test_kit.tar.gz
cp -r wheel_sidechain_test_kit/tools ./
chmod +x tools/run_wheel_probe_board.sh
```

如果项目已安装好 `venv-gst/`，直接运行：

```bash
./tools/run_wheel_probe_board.sh \
  --config configs/config.json \
  --wheel-photo-url http://<PC_IP>:28014/api/vehicle/wheel-photo \
  --duration 120 \
  --target-fps 10 \
  --force-event-driven false
```

如果要临时覆盖左右车轮 RTSP：

```bash
./tools/run_wheel_probe_board.sh \
  --config configs/config.json \
  --left-source 'rtsp://user:pass@left-camera/stream' \
  --right-source 'rtsp://user:pass@right-camera/stream' \
  --wheel-photo-url http://<PC_IP>:28014/api/vehicle/wheel-photo \
  --duration 120 \
  --target-fps 10 \
  --force-event-driven false
```

如果板端 Python 不在 `venv-gst/bin/python`，指定：

```bash
PYTHON_BIN=/path/to/python ./tools/run_wheel_probe_board.sh ...
```

## 4. 板端输出

脚本会输出解析后的配置，例如：

```json
{
  "wheel_enabled": true,
  "left_source": "...",
  "right_source": "...",
  "model": ".../models/wheel/2026.4.28CRwheel.rknn",
  "wheel_photo_url": "http://<PC_IP>:28014/api/vehicle/wheel-photo"
}
```

运行中会周期性输出：

```text
[status] stats=... history=... locked=...
```

重点看：

- `reader.frames` 是否增长。
- `processor.frames` 是否增长。
- `history.left.buckets` / `history.right.buckets` 是否增长。
- `locked` 是否出现 `left` 或 `right`。

板端保存目录：

```text
wheel_probe_output/YYYYMMDD_HHMMSS/
  resolved_settings.json
  summary.json
  wheel_photo_queue.db
```

车轮照片落盘目录：

```text
<system.wheel_photo_base_dir>/box/YYYYMMDD/HH/
```

默认是：

```text
/data/ftp/box/YYYYMMDD/HH/
```

## 5. 验收标准

一次有效测试应满足：

- 板端没有模型加载失败、RTSP 打不开、RKNN runtime 初始化失败。
- `summary.json` 里的 `photos` 非空。
- PC 端 `wheel_photo_requests.jsonl` 非空。
- 每条请求至少包含：

```json
{
  "photoUrl": "box/...",
  "type": "4",
  "cleanValue": 1
}
```

字段含义：

- `type=4`：左侧车轮照片。
- `type=5`：右侧车轮照片。
- `cleanValue=1/2/3/4`：对应 `0-25/25-50/50-75/75-100`。

## 6. 常见问题

### PC 没收到请求

检查：

- 板端 `--wheel-photo-url` 是否使用 PC 局域网 IP，不要写 `127.0.0.1`。
- PC 防火墙是否放行 28014 端口。
- 板端能否访问 PC：

```bash
curl http://<PC_IP>:28014/health
```

### 板端没有 history

检查：

- 左右 RTSP 是否能打开。
- 车轮画面里是否有车轮经过。
- `target_fps` 是否太低。
- 模型路径是否正确。

### 有 history 但没有 PC 请求

检查：

- `summary.json` 里的 `photos` 是否非空。
- `wheel_photo_queue.db` 是否有 pending。
- PC mock 是否还在运行。

### 只想本地看结果，不上报 PC

不传 `--wheel-photo-url` 即可。脚本会把 payload 写入：

```text
wheel_probe_output/YYYYMMDD_HHMMSS/local_wheel_photo_payloads.jsonl
```
