# 当前性能与配置决策

本文是 2026-07 后性能优化类文档的收口版本。旧的现场分析、初步方案和甲方确认表已经合并到这里；具体运行事实仍以当前代码、`configs/config.json`、`configs/config_绕行.json` 和 Web 配置页为准。

## 当前结论

- 当前四路压力主要来自 CPU、内存带宽、rawvideo 帧搬运、JPEG 编码、单车视频编码和温度叠加，不是单纯 NPU 算力不够。
- RGA 在本项目高负载场景存在板端死机风险，禁止作为现场优化手段。强约束见 `../RGA运行默认策略.md`。
- 默认采用事件图片路径上报：`system.api.capture_mode=path`。
- 事件图片保存到 `/data/ftp/event_captures/<配置名>/YYYYMMDD/HH/`，平台按 `captureImage` 路径取图。
- 本地事件 JSON 留存由 `logic.enable_event_disk` 控制，默认关闭；平台上报不受影响。
- per-id 单车视频仍保留，默认目录 `/data/ftp/per_id`，不可写时运行时回退到 `video_result/per_id/`。
- 冲洗道优先暂停绕行道为可选功能，默认关闭。开启后冲洗道 Zone A 有车时会暂停目标绕行配置的读流/推理，type5 后按配置延迟恢复。

## 当前默认配置口径

主配置和绕行配置的关键默认值：

```json
{
  "system": {
    "api": {
      "capture_mode": "path"
    }
  },
  "logic": {
    "enable_event_disk": false,
    "enable_per_id_video": true,
    "per_id_video_dir": "/data/ftp/per_id"
  },
  "event_capture_dir": "/data/ftp/event_captures/config",
  "event_capture_quality": 70,
  "wheel": {
    "pause_bypass_during_wash_enabled": false,
    "pause_bypass_config_key": "config_绕行.json",
    "pause_bypass_resume_delay_seconds": 0.5
  }
}
```

绕行配置的 `event_capture_dir` 使用 `/data/ftp/event_captures/config_绕行`。

## Web 可配置项

用户参数里重点确认：

- `截图上报方式`
  - `path`：平台收到图片路径，本地必须保留事件图片。
  - `base64`：平台收到图片数据，本地图片仍会生成，但不再是平台取图必需条件。
- `事件图片目录`
  - 建议保持 `/data/ftp/event_captures/<配置名>`，便于平台和现场人员按日期回查。
- `保存本地事件 JSON`
  - 默认关闭，减少本地历史文件。
  - 若需要离线排查完整事件 JSON，可临时开启。
- `冲洗道有车时暂停绕行道`
  - 默认关闭，避免绕行道盲区。
  - 开启前需确认甲方接受冲洗道作业期间绕行道暂时不检测。

开发者参数里重点确认：

- `event_capture_quality=70`
- `video.debug_frame_path=off` 或留空使用命名空间默认路径
- `wheel.target_fps` / `wheel.active_target_fps`
- `logic.plate_infer_stride`

## 保留的强约束

### RGA

不允许开启 RGA：

- 不添加 `video.rga_enable`。
- 不通过环境变量启用 RGA。
- 不把 `future_modules/acceleration/rga_resize_plugin.py` 接回主流程。

原因见 `../RGA运行默认策略.md`。

### 多路运行

- 每份配置的 `system.device_id` 必须唯一。
- `command_dir`、`heartbeat_path`、`startup_flag_path`、`debug_frame_path` 留空或保持旧默认值时，运行时会自动收口到 `/dev/shm/cleaningcar_runtime/<device_id>/`。
- Web 调用多路推理接口时必须带 `key=<配置文件名>`。

## 现场优先排查顺序

1. 看 Web `/inference/health?key=<配置名>`，确认进程、心跳、`runtime_namespace_key` 正常。
2. 看 `logs/inference/` 最新日志里的 `[diag]`：
   - `pipeline_backpressure`
   - `main_reader_reconnect`
   - `wheel_reader_reconnect`
   - `per_id_video_issue`
   - `upload_backlog`
   - NPU/温度标志
3. 看 `/data/ftp/event_captures/<配置名>/YYYYMMDD/HH/` 是否持续生成事件图片。
4. 看 `/data/ftp/box/YYYYMMDD/HH/` 是否有重复车轮照片或单侧长期无 hit。
5. 看 `/data/ftp/per_id/` 或 `video_result/per_id/` 的单车视频是否排队/丢帧。

## 仍需甲方确认的调整

以下调整会影响接口、图片、视频或绕行业务窗口，不能无确认直接作为正式默认策略：

- 事件图片是否可以长期只用 path，不再使用 base64。
- 事件图片保留周期和 `/data/ftp` 可用容量。
- 单车视频是否允许降帧率或降分辨率。
- 车轮相机是否可提供低码率或子码流。
- 绕行道是否接受冲洗道优先暂停带来的检测盲区。
- 绕行道是否强依赖高频车牌识别。
