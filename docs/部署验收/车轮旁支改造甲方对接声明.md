# 车轮旁支照片接口使用说明

本文只说明甲方平台如何接收和使用车轮旁支照片结果。

## 1. 需要提供的接口

甲方平台需要提供一个车轮照片接收接口：

```text
POST /api/vehicle/wheel-photo
Content-Type: application/json
```

如果平台需要鉴权，板端会使用配置里的 `system.api.token`，请求头格式为：

```text
Authorization: Bearer <token>
```

## 2. 板端接口地址怎么填

板端配置文件为：

```text
configs/config.json
```

推荐配置方式：

```json
{
  "system": {
    "api": {
      "url": "http://平台IP:端口/api/vehicle/wash-event",
      "token": "",
      "capture_mode": "path",
      "wheel_photo_url": ""
    }
  }
}
```

说明：

- `capture_mode=path` 是当前默认主事件截图上报方式，平台收到 `captureImage` 路径后按文件路径取图。
- 车轮照片接口独立使用 `photoUrl` 字段，仍按本文第 4 节的相对路径规则对接。

`wheel_photo_url` 留空时，板端会自动从 `url` 推导：

```text
http://平台IP:端口/api/vehicle/wash-event
-> http://平台IP:端口/api/vehicle/wheel-photo
```

如果甲方车轮照片接口不是这个路径，直接显式填写完整地址：

```json
{
  "system": {
    "api": {
      "url": "http://平台IP:端口/api/vehicle/wash-event",
      "wheel_photo_url": "http://平台IP:端口/实际车轮照片接口"
    }
  }
}
```

## 3. 甲方会收到的数据

板端每张车轮照片会上报一条 JSON：

```json
{
  "photoUrl": "box/20260621/14/143025_12_left_1.jpg",
  "type": "4",
  "cleanValue": 2
}
```

同一侧车轮图片按 1 秒一个时间桶汇总。每个时间桶最终上报一张代表图，代表图选择检测框中心离画面中心最近的图片。

字段说明：

| 字段 | 类型 | 示例 | 说明 |
| --- | --- | --- | --- |
| `photoUrl` | string | `box/20260621/14/143025_12_left_1.jpg` | 车轮图片相对路径。 |
| `type` | string | `4` | 车轮侧别，`4` 表示左侧车轮，`5` 表示右侧车轮。 |
| `cleanValue` | integer | `2` | 车轮清洁度档位，取值为 `1/2/3/4`。 |

`cleanValue` 对应关系：

| cleanValue | 模型档位 |
| --- | --- |
| 1 | `0-25` |
| 2 | `25-50` |
| 3 | `50-75` |
| 4 | `75-100` |

## 4. 图片保存在哪里

板端图片根目录由配置项控制：

```json
{
  "system": {
    "wheel_photo_base_dir": "/data/ftp"
  }
}
```

默认根目录：

```text
/data/ftp
```

车轮图片实际保存路径格式：

```text
<wheel_photo_base_dir>/box/YYYYMMDD/HH/{session}_{track_id}_{side}_{seq}.jpg
```

默认示例：

```text
/data/ftp/box/20260621/14/143025_12_left_1.jpg
/data/ftp/box/20260621/14/143025_12_right_1.jpg
```

上报给甲方的 `photoUrl` 是相对路径，不带 `/data/ftp` 前缀：

```text
box/20260621/14/143025_12_left_1.jpg
box/20260621/14/143025_12_right_1.jpg
```

文件名含义：

| 片段 | 示例 | 说明 |
| --- | --- | --- |
| `session` | `143025` | 正常运行时为主检测进程初始化事件管理器的时间，格式为 `HHMMSS`；单独车轮测试工具会使用 `probe_HHMMSS`。 |
| `track_id` | `12` | 板端车辆轨迹 ID。 |
| `side` | `left` / `right` | 左侧或右侧车轮。 |
| `seq` | `1` | 同一车辆同侧车轮图片序号。 |

甲方平台如果需要展示图片，需要把 `photoUrl` 和板端文件服务根路径拼接。例如板端 `/data/ftp` 映射为：

```text
http://板端IP:文件服务端口/
```

则图片访问地址为：

```text
http://板端IP:文件服务端口/box/20260621/14/143025_12_left_1.jpg
```

## 5. 联调检查方法

甲方接口收到请求后，至少检查三点：

- `photoUrl` 非空，并能拼出可访问的图片地址。
- `type` 为 `4` 或 `5`。
- `cleanValue` 为 `1/2/3/4`。

PC 端可临时启动 mock 接口检查板端是否正常上报：

```bash
python tools/mock_wheel_photo_api.py --host 0.0.0.0 --port 28014
```

板端测试时把接口地址指向 PC：

```bash
./tools/run_wheel_probe_board.sh \
  --config configs/config.json \
  --wheel-photo-url http://<PC_IP>:28014/api/vehicle/wheel-photo \
  --duration 120 \
  --target-fps 10 \
  --force-event-driven false
```

mock 接口收到后会在 PC 端保存：

```text
mock_api_output/YYYYMMDD_HHMMSS/wheel_photo_requests.jsonl
```

里面每行是一条收到的车轮照片上报 JSON。
