# 环境目录说明

## `packages/`

用途：

- 存放 RKNN 运行依赖
- 存放 `rknn_toolkit_lite` 的 wheel 包
- 存放 `librknnrt.so`
- 可选存放 RGA 相关库和头文件

`install_runtime_venv.sh` 会优先从这里安装或复制运行依赖。

当前仓库现状：

- 已包含 `librknnrt.so`
- 已包含 `im2d.h`
- 当前默认未包含 `librga.so`

这意味着安装脚本具备 RGA 依赖复制逻辑，但当前仓库并不等于已经自带完整 RGA 运行库。

## `venv-gst/`

用途：

- 项目的 Python 虚拟环境
- 一般包含 `fastapi`、`uvicorn`、`opencv`、`Pillow`、项目依赖和 RKNN Python 包

说明：

- 如果该目录是从别的设备直接拷贝过来的，可能因 Python 路径或系统环境不同而失效
- 失效时可直接执行：

```bash
FORCE_SETUP=1 ./install_runtime_venv.sh
```

## 根目录四个脚本

### `install_runtime_venv.sh`

用途：

- 检查 `configs/config.json`
- 检查或重建 `venv-gst/`
- 安装系统依赖
- 从 `packages/` 安装 RKNN / RGA 依赖
- 安装 `requirements.txt`

说明：

- 只安装环境，不启动 Web
- 只有当 `packages/` 下实际存在对应文件时，才会复制 RGA 相关库

### `start_web_server.sh`

用途：

- 手工管理 Web 服务
- 支持 `start|stop|restart|status`
- 后台启动时输出 pid 文件与日志文件

建议用法：

- `./start_web_server.sh` 会直接调用 `venv-gst/bin/python`
- 所以安装完环境后，可以**不激活虚拟环境直接运行脚本**
- 只有你要手工执行 `python -m web.server`、`python run_zone_detect.py` 这类 Python 命令时，才建议先 `source venv-gst/bin/activate`

```bash
./start_web_server.sh start
```

### `install_runtime_venv.sh`

用途：

- 安装或修复 `venv-gst/`
- 安装系统依赖、Python 依赖、RKNN/RGA 运行库
- 由 `start_web_server.sh` 自动调用

说明：

- 甲方一般不需要手工执行
- 如果甲方需要 `systemd`，请按根目录 `README.md` 自行创建 service 文件

## 推荐板端使用方式

- 把 `packages/` 跟项目一起带到 RKNN 平台
- `venv-gst/` 可以一起带过去，但不要假定一定能直接用
- 直接执行 `./start_web_server.sh start`
- 如需服务化，由甲方按根目录 `README.md` 自行配置 `systemd`
