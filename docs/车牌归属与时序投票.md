# 车牌归属与时序投票

主链路的双模型车牌检测、透视矫正、双层车牌拼接与OCR保持原实现。车牌在同帧明确属于唯一车辆时，直接把原始号码和该次置信度交给EventManager；不再等待独立车牌tracker先锁字或两次绑定。多车归属歧义、同一车同一帧多个合格异牌不计票；大面积截断车辆的上部防串牌规则保留。未绑定的旧观测不自动补给后来出现的车辆。

每辆车只有一份号码证据：检测置信度至少0.65、OCR至少0.75、号码格式有效，同一源帧只能记一次。初锁默认在最近2秒取得至少4票且占有效票70%；间歇无车牌或未执行OCR不清票，也不构成新票。窗口使用真实捕获时间，不按源帧间隔强制清零。已锁号码纠错默认在最近6秒取得另一个号码至少12票且占80%。证据最多60条，不保存全帧/JPEG。

新track使用自己的近期证据形成临时车牌身份（默认2票），与旧event身份不同就拒绝handoff。有合格候选但没有多数时仍等待身份确认，不退回无牌空间续接。只有已经确认同车handoff后才合并有界证据和继承正式号码，避免先借旧号码再证明同车。原有handoff次数、时限、方向和空间限制继续适用。

type1可以先空牌及时创建事件；后续阶段和type5使用同一event ID携带已锁号码。平台需用后补有效牌号覆盖旧空值。颜色锁定、黄绿融合与现有上传格式不变，颜色不足不阻挡已确认号码。

旧logic.plate_track_lock_frames和logic.plate_text_max_streak_gap_frames保留配置加载兼容，但不再控制主链路，也不再显示为有效调节项。旧车牌绑定缓存辅助函数仅供兼容测试使用，不在实时主链路创建状态。

性能日志中的w0:...fps/...ms仍为主模型NPU耗时。新增plate=...fps/...ms记录车牌真实调用频率与完整车牌链路平均耗时；full=...ms记录worker预处理、主检测、车牌及结果打包的平均耗时，不包含下游业务/录像耗时。指标同时写入perf.workers的plate_fps、plate_ms、total_ms、plate_calls_delta。

初锁、纠错和type5收尾输出[plate-vote]轻量日志，便于区分未识别、证据不足、已锁定和号码修正。logic.plate_infer_stride仍单独控制识别频率；冲洗的plate_requires_vehicle和绕行提前识别条件未改。

## 未锁事件收尾补锁

冲洗模板开启logic.plate_finalize_fallback_enabled，绕行模板关闭；两份模板车牌均每帧检查。初锁仍用2秒4票70%，不为了补历史单票降低置信度。

仅在type5、车辆业务已确认且type2已成立、没有待判handoff或被新track取代时，对尚未锁字的事件检查全程计数：同号至少4票，第一名票数至少为第二名2倍。独立完整号码得到至少2票、与第一名差异达到3个字符时视为明显身份冲突，不补锁。候选最多32种，达到上限或handoff观测区间重叠时保守留空，不通过淘汰竞争号码制造多数。快锁后停止全程计数，已有锁定不会被补锁覆盖；近期证据仍用于原纠错规则。

计数只使用已唯一归属且通过原检测/OCR门槛的不同源帧，不存额外图片。成功补锁更新同一event的type5最终号码和业务状态，不重开事件。type6平台接口保持原id/type/lane/perIdVideoEnabled字段集合，不携带车牌；type5负责最终牌号。

配置：logic.plate_finalize_min_votes=4、plate_finalize_runner_up_ratio=2.0、plate_finalize_max_candidates=32。日志新增[plate-vote] action=finalize_lock/finalize_skip及拒绝原因。单票场景仍保留未锁状态，局部再识别需另做受控验证。

## CSV审计

保留旧CSV前十列顺序，追加capture_ts、plate_text_conf、plate_type、landmarks、plate_binding、plate_vote_eligible。eligible表示当前观测满足入票条件，不代表号码已经锁定。CSV按秒批量flush，避免1MiB缓冲令低事件量时文件长期为空，不逐帧fsync。未来回放应使用实际捕获时间和OCR分数；旧CSV缺字段时不得把候选回放数量换算为实机正确率。
