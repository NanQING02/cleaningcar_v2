# 甲方平台适配说明

本文档以当前仓库代码和配置为准，说明甲方平台接收事件、车道信息和图片路径时必须适配的字段契约。

当前交付口径是：图片不再按 base64 上报，统一按板端绝对路径上报。

## 接口不变

主事件接口不变：

```text
POST /api/vehicle/wash-event
Content-Type: application/json
Authorization: Bearer <token>
```

车轮照片批量接口不变：

```text
POST /api/vehicle/wheel-photo
Content-Type: application/json
Authorization: Bearer <token>
```

## 必须调整的字段

| 接口 | 字段 | 当前类型 | 当前含义 | 甲方平台接收要求 |
| --- | --- | --- | --- | --- |
| `wash-event` | `lane` | string | 车道名称 | 必须按字符串接收 |
| `wash-event` | `captureImage` | string | 事件截图绝对路径 | 必须按路径字符串接收，不按 base64 解码 |
| `wash-event` | `wheelResults[].photoUrl` | string | 车轮图片绝对路径 | 必须按路径字符串接收 |
| `wash-event` | `wheelResults[].imageBase64` | 无 | 旧字段 | 当前版本不再上报，平台不得依赖该字段 |
| `wheel-photo` | `photoUrl` | string | 车轮图片绝对路径 | 必须按路径字符串接收 |

## 车道信息

主事件 `wash-event` 里使用 `lane` 字段表示车道。

当前两份配置的实际取值如下：

| 配置文件 | `logic.lane_name` | 上报字段 |
| --- | --- | --- |
| `configs/config.json` | `冲洗` | `"lane": "冲洗"` |
| `configs/config_绕行.json` | `绕行` | `"lane": "绕行"` |

`lane` 字段是字符串，不是数字。平台接收模型、数据库字段、接口校验和前端展示都必须允许字符串值 `冲洗`、`绕行`。

`wash-event` 的 `type=1`、`type=2`、`type=3`、`type=4`、`type=5` 都会携带 `lane`。`type=6` 只会上报：

```json
{
  "id": "RK3588-DEV-202607132100-12",
  "type": 6,
  "lane": "冲洗"
}
```

平台判断车道时以 `lane` 字段为准。

## 事件截图字段

当前配置为：

```json
{
  "system": {
    "api": {
      "capture_mode": "path"
    }
  },
  "event_capture_dir": "/data/ftp/event_captures/config"
}
```

`captureImage` 当前上报板端绝对路径：

```json
{
  "captureImage": "/data/ftp/event_captures/config/20260713/21/20260713_210036_RK3588-DEV_12_t5_f889.jpg"
}
```

平台需要把 `captureImage` 字段定义为普通字符串路径。当前版本不按 base64 接收，也不需要从该字段解码图片内容。

如果平台通过 HTTP 或 FTP 展示图片，路径映射关系如下：

```text
板端文件：
/data/ftp/event_captures/config/20260713/21/a.jpg

文件服务根目录：
/data/ftp

HTTP 路径：
http://板端IP/event_captures/config/20260713/21/a.jpg
```

## 主事件车轮结果

`type=5` 主事件会附加该车生命周期内锁定的左右车轮结果。当前字段为 `wheelResults[].photoUrl`，不再提供 `wheelResults[].imageBase64`。

示例：

```json
{
  "id": "RK3588-DEV-202607132100-12",
  "type": 5,
  "captureTime": "2026-07-13 21:00:36",
  "lane": "冲洗",
  "captureImage": "/data/ftp/event_captures/config/20260713/21/20260713_210036_RK3588-DEV_12_t5_f889.jpg",
  "plateNumber": "鲁A12345",
  "vehicleType": "小汽车",
  "wheelResults": [
    {
      "side": "left",
      "captureTime": "2026-07-13 21:00:30",
      "photoUrl": "/data/ftp/box/20260713/21/143025_12_left_1.jpg",
      "className": "50-75"
    },
    {
      "side": "right",
      "captureTime": "2026-07-13 21:00:31",
      "photoUrl": "/data/ftp/box/20260713/21/143025_12_right_1.jpg",
      "className": "75-100"
    }
  ]
}
```

`wheelResults` 子项字段如下：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `side` | string | `left` 或 `right` |
| `captureTime` | string | 车轮图片捕获时间 |
| `photoUrl` | string | 车轮图片绝对路径 |
| `className` | string | 车轮清洁度模型分类，取值为 `0-25`、`25-50`、`50-75`、`75-100` |

平台接收模型中不要再把车轮图片字段定义为 `imageBase64`。当前版本字段名是 `photoUrl`，字段值是 `/data/ftp/box/...jpg` 这种绝对路径。

## 车轮照片批量接口

车轮照片批量接口 payload：

```json
{
  "photoUrl": "/data/ftp/box/20260713/21/143025_12_left_1.jpg",
  "type": "4",
  "cleanValue": 3
}
```

字段定义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `photoUrl` | string | 车轮图片绝对路径 |
| `type` | string | 车轮侧别，左侧为 `"4"`，右侧为 `"5"` |
| `cleanValue` | number | 清洁度值，`0-25` 为 1，`25-50` 为 2，`50-75` 为 3，`75-100` 为 4 |

该接口当前不携带 `lane` 字段。车道信息来自主事件 `wash-event.lane`。

车轮照片发送机制：

- 旁路识别到车轮后，不逐帧调用 HTTP 接口。
- 当前按 `wheel.photo_bucket_seconds=0.25` 分桶。
- 每个车、每侧、每个 0.25 秒桶最多保留一张代表图。
- `wheel.photo_min_score=0.3` 以下的结果不入桶。
- 最终 `type=5` 事件触发时，该车生命周期内的代表图一次性写入上传队列。
- 上传队列由后台线程异步发送到 `/api/vehicle/wheel-photo`。
- 同一个 `photoUrl` 可能因重试再次到达，平台按 `photoUrl` 做唯一性处理。

## 文件路径规则

当前图片都在板端 `/data/ftp` 下。

事件截图路径：

```text
/data/ftp/event_captures/<配置名>/<YYYYMMDD>/<HH>/<文件名>.jpg
```

车轮图片路径：

```text
/data/ftp/box/<YYYYMMDD>/<HH>/<文件名>.jpg
```

平台通过 HTTP 展示图片时，路径转换规则是去掉文件服务根目录 `/data/ftp`，保留后续路径。

```text
板端路径：
/data/ftp/box/20260713/21/143025_12_left_1.jpg

HTTP 路径：
http://板端IP/box/20260713/21/143025_12_left_1.jpg
```

## 平台代码改造点

平台需要完成以下改造：

1. `wash-event` 接收模型中，`lane` 字段定义为 string。
2. `wash-event` 接收模型中，`captureImage` 字段定义为 string 路径。
3. `wash-event` 接收模型中，`wheelResults` 子项使用 `photoUrl` 字段，类型为 string 路径。
4. 平台不要再要求 `wheelResults[].imageBase64` 必填。
5. 平台不要再对 `captureImage` 或 `wheelResults[].photoUrl` 执行 base64 解码。
6. `/api/vehicle/wheel-photo` 接收模型中，`photoUrl` 字段定义为 string 路径。
7. 数据库如保存图片字段，字段内容保存路径字符串。
8. 图片展示时，按 `/data/ftp` 文件根目录映射为实际可访问 URL。
9. 车道展示、查询、统计以 `lane` 字段为准，当前值为 `冲洗` 或 `绕行`。

## 验收条件

联调时必须满足以下条件：

- `wash-event` 收到 `"lane": "冲洗"` 时能正常入库。
- `wash-event` 收到 `"lane": "绕行"` 时能正常入库。
- `wash-event.captureImage` 收到 `/data/ftp/event_captures/...jpg` 时不触发 base64 解码。
- `type=5` 事件收到 `wheelResults[].photoUrl=/data/ftp/box/...jpg` 时能正常入库。
- `type=5` 事件不包含 `wheelResults[].imageBase64` 时能正常入库。
- `/api/vehicle/wheel-photo` 收到 `photoUrl=/data/ftp/box/...jpg` 时能正常入库。
- 平台能根据 `captureImage` 打开事件截图。
- 平台能根据 `wheelResults[].photoUrl` 打开车轮图片。
- 平台能根据 `wheel-photo.photoUrl` 打开批量车轮图片。
