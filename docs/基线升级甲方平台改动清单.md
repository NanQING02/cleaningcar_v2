# 基线升级甲方平台改动清单

> 对比基线：`a4d11f0e50392aba07746f12fbe219e321a7d8d7`（已交付版本）
> 当前版本：`client-product-update` 分支 HEAD（含业务演进 + 资源优化 + 分冲洗时长）
> 整理日期：2026-09-29。所有结论均经过两版代码字段级 diff 核实。

## 一、平台必须改动的部分

### 1. `plateColor` 新增取值"黄绿色"（必改）

基线版本无此取值。车牌颜色枚举校验、数据库字段约束、前端展示映射需要新增 `黄绿色`。
黄绿牌跨帧融合后直接上报 `plateColor="黄绿色"`，同时 `plateColorConfidence` 携带融合置信度。

### 2. `type=5` 事件新增两个分冲洗时长字段（必改）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `manualWashDuration` | number | 人工冲洗时长（秒，保留2位小数），未检测到人工时为 `0` |
| `cleaningTableWashDuration` | number | 清洗台冲洗时长（秒，保留2位小数），未检测到清洗台时为 `0` |

注意：两者之和可能大于 `totalWashDuration`（总时长为两类时间的并集口径，同帧两类并存各计一次）。
原有 `totalWashDuration` 字段与口径完全不变。字段只在 `type=5` 携带。

### 3. `type=5` 事件新增两个条件字段（必改：需容忍新字段）

15 分钟强制闭环等异常收尾场景下出现，正常过车不携带：

| 字段 | 类型 | 出现场景 |
| --- | --- | --- |
| `forceVideoStop` | boolean | 强制闭环时视频停止标记 |
| `forcedCompletionReason` | string | 强制闭环原因（如 `type2_dwell_timeout_15m`） |

JSON 反序列化需忽略未知字段或显式接收，不得因新字段报错。

### 4. 事件 `id` 格式与长度规范（需核对）

- 基线格式：`{device_name}-{时间戳}-{track_id}`，长度不定
- 现格式：`{camera}-{毫秒时间戳}-{10位hex}`，**规范为不超过 36 字符**（超长历史 ID 稳定哈希压缩）
- 平台 ID 字段按 string(36) 接收；同一辆车 type1-6 的 `id` 一致（一车一事件）

## 二、平台建议知道的行为变化（不改代码也能运行）

1. **事件数量分布变化**：
   - type4 缺失时会在 type5 前补发 → `type=4` 数量比基线**多**
   - 一车一事件 + 轨迹 ID 交接收紧 → 抖动/重复事件比基线**少**
   - 15 分钟未完成闭环的车辆也会发出 type5 收尾（带异常原因）
2. **`abnormalReason` 枚举扩充**：新增 `TRACK_LOST_IN_ZONE_A_TIMEOUT`、`OVER_15_MINUTES_AFTER_TYPE2`、区内出生类等取值，拼接符仍为 `|`
3. **`direction` / `directionLabel` 判定算法更换**（方向感知锚点+参考边）：取值域不变，数值分布会与基线不同（业务修正，更准）
4. **上传顺序更严格**：同一 event ID 的 type1-6 严格按阶段串行到达，重试后不越序；平台按序处理逻辑可简化
5. **车轮照片内容变化**：`photoUrl` 字段与接口不变，图片从整帧画面变为车轮检测框扩边特写（无标注原图，单张从 200-400KB 降至 5-15KB）。若平台有人工复核界面，展示范围变小；如需回退整帧，配置 `wheel.photo_crop_margin_ratio=-1`

## 三、明确不需要改动的部分（与基线一致，已核实）

- `wash-event` / `wheel-photo` 接口 URL、鉴权方式、JSON 顶层结构
- type1-6 字段集合（除上述新增外逐字段一致）
- `wheelResults` 条目四字段 `side` / `captureTime` / `photoUrl` / `className`
- 车轮照片批量上报接口（基线已有）
- `captureImage` 路径字符串模式（基线即 path 模式）
- `type=6` 的 `perIdVideoEnabled` 字段（基线已有）
- 事件截图、单车录像的文件路径交付口径

## 四、时间口径说明

所有上报时间（`captureTime`、`washStartTime`、`washEndTime`、`wheelResults[].captureTime`、心跳时间戳）均为板端系统时钟的实时本地时间，已逐字段核实。板端当前未配置 NTP，建议交付时确认板子时钟同步方式（甲方网络内网 NTP 或定期校时），否则长期漂移会平移全部时间。

## 五、建议的验收要点

1. 用带黄绿牌的车辆回放，确认平台能接收 `plateColor="黄绿色"`
2. 触发一次人工冲洗 + 清洗台冲洗混合场景，核对 `manualWashDuration` + `cleaningTableWashDuration` 与 `totalWashDuration` 的关系（和可大于总）
3. 构造一次超时闭环（或回放长停留视频），确认平台对 `forceVideoStop`/`forcedCompletionReason` 不报错
4. 核对事件 ID 长度入参校验（≤36 字符）
5. 确认平台对新增 type4 补发事件的统计口径（如按 type4 计数统计冲洗次数，数值会比基线高）
