# RK3588 定频说明

本仓库新增了一个参考 `rknn-3588-npu-yolo-accelerate-saturated` 思路的板端定频脚本：

- [tools/rk3588_fixed_freq.sh](/home/serve/cleaningcar_v2/tools/rk3588_fixed_freq.sh:1)

目标不是照搬固定频点，而是：

- 自动读取当前板子的 CPU / NPU / DDR / GPU `max_freq`
- 优先使用 `performance` governor
- 若节点不支持 `performance`，再回退到 `userspace`
- 保存原始 governor / cpuidle 状态，支持后续恢复

## 用法

查看当前状态：

```bash
bash tools/rk3588_fixed_freq.sh status
```

应用定频：

```bash
bash tools/rk3588_fixed_freq.sh apply
```

恢复原始状态：

```bash
bash tools/rk3588_fixed_freq.sh restore
```

## 项目内接入

`run_zone_detect.py` 启动推理时默认会尝试执行定频脚本。以下任一方式可显式关闭：

- 环境变量 `CLEANINGCAR_PERF_LOCK=0`
- 或配置项 `system.performance_lock_enabled=false`

若脚本不存在、权限不足或板端节点不支持，程序只打印 warning，不阻断推理启动。

默认不会自动恢复频率；如需在进程退出时恢复，可开启：

- 环境变量 `CLEANINGCAR_PERF_LOCK_RESTORE_ON_STOP=1`
- 或配置项 `system.performance_lock_restore_on_stop=true`

如需禁止自动走 `sudo -n`，可设置：

- 环境变量 `CLEANINGCAR_PERF_LOCK_USE_SUDO=0`

## 建议口径

- 长稳压测、双路压测、NPU 已接近饱和时，优先开启
- 现场首次接入时先跑 `status`
- 如果板端没有 root 或免密 sudo，脚本会失败并打印 warning，但不会阻断推理启动
